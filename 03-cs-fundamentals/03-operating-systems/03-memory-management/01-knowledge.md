# 03. Memory Management (Knowledge & Theory)

## Learning Objectives
- অপারেটিং সিস্টেম কীভাবে RAM (Main Memory) ম্যানেজ করে তা বোঝা।
- Contiguous Memory Allocation এবং Fragmentation (Internal ও External) সম্পর্কে ক্লিয়ার আইডিয়া পাওয়া।
- **Paging** কীভাবে External Fragmentation দূর করে তা বোঝা।
- **Virtual Memory** এর ম্যাজিক এবং Page Fault সম্পর্কে জানা।

---

## 1. Why do we need Memory Management?

যেকোনো সফটওয়্যার রান করতে হলে তাকে আগে হার্ডডিস্ক থেকে **RAM (Main Memory)** তে আসতে হয়, কারণ CPU সরাসরি হার্ডডিস্ক থেকে ডেটা পড়তে পারে না (পড়লেও সেটি অনেক স্লো হবে)। 
আপনার পিসির RAM হয়তো ৮ জিবি, কিন্তু আপনি একই সাথে ক্রোম, গেমস, ওয়ার্ড এবং ভিডিও প্লেয়ার ওপেন করে রেখেছেন, যাদের মোট সাইজ হয়তো ১২ জিবি। 
এই ৮ জিবি জায়গায় ১২ জিবির অ্যাপ কীভাবে ফিজিক্যালি জায়গা করে নিচ্ছে এবং কেউ যেন কারও জায়গা দখল করে না ফেলে—এই পুরো ম্যানেজমেন্টের দায়িত্বই হলো OS এর Memory Manager এর।

---

## 2. Contiguous Memory Allocation (পুরানো পদ্ধতি)

আগের দিনের OS গুলো একটি প্রসেসকে RAM এর একটি টানা বা সিরিয়াল জায়গায় (Contiguous block) রাখতো।
যেমন: একটি ৩ জিবির গেম ওপেন করলে, RAM এর ভেতরে ঠিক ৩ জিবি টানা ফাঁকা জায়গা খুঁজে বের করে গেমটিকে সেখানে বসানো হতো। 

**সমস্যা: Fragmentation (টুকরো হয়ে যাওয়া)**
- **External Fragmentation:** ধরা যাক, আপনার RAM এ টোটাল ৫ জিবি জায়গা ফাঁকা আছে। কিন্তু সেই ৫ জিবি এক জায়গায় টানা ফাঁকা নেই। ১ জিবি করে ৫টি আলাদা আলাদা জায়গায় ফাঁকা হয়ে আছে। এখন আপনি যদি ৪ জিবির একটি অ্যাপ ওপেন করতে যান, OS বলবে "মেমোরি ফুল!"। কারণ টোটাল ৫ জিবি ফাঁকা থাকলেও, টানা ৪ জিবি ফাঁকা জায়গা নেই। এটিই হলো External Fragmentation।
- **Internal Fragmentation:** OS যদি আপনাকে একটি ৪ জিবির ব্লক দেয়, কিন্তু আপনার অ্যাপের সাইজ ৩.৫ জিবি হয়, তবে বাকি ০.৫ জিবি জায়গা ব্লকটির ভেতরে চিরতরে নষ্ট হয়ে পড়ে থাকবে। কেউ তা ব্যবহার করতে পারবে না। একেই Internal Fragmentation বলে।

---

## 3. The Magic of Paging (বইয়ের পাতার মতো ভাগ করা)

External Fragmentation এর সমস্যা সমাধানের জন্য আধুনিক OS গুলো **Paging** পদ্ধতি ব্যবহার করে।

**কীভাবে কাজ করে?**
- OS পুরো ফিজিক্যাল RAM কে সমান ছোট ছোট টুকরোতে ভাগ করে ফেলে (যেমন: 4KB এর টুকরো)। এদেরকে বলা হয় **Frames**।
- একইভাবে, আপনার অ্যাপ বা প্রসেসটিকেও সমান ছোট ছোট টুকরোতে ভাগ করা হয়। এদেরকে বলা হয় **Pages**। (Frame এবং Page এর সাইজ সবসময় সমান হয়)।
- এখন আর অ্যাপকে RAM এর টানা জায়গায় থাকতে হবে না। অ্যাপের একটি Page হয়তো RAM এর শুরুতে আছে, আরেকটি Page হয়তো মাঝখানে আছে, আর আরেকটি শেষে আছে। 

**সুবিধা:** 
যেহেতু অ্যাপটি টুকরো টুকরো হয়ে RAM এর যেকোনো ফাঁকা জায়গায় বসতে পারে, তাই External Fragmentation এর সমস্যা পুরোপুরি দূর হয়ে যায়। 

**Page Table:** 
অ্যাপের কোন Page টি RAM এর কোন Frame এ আছে, তার হিসাব রাখার জন্য OS একটি টেবিল মেইনটেইন করে, যাকে Page Table বলে। CPU যখন ডেটা চায়, সে এই টেবিল দেখে ফিজিক্যাল অ্যাড্রেস খুঁজে বের করে।

## 4. Virtual Memory (অবাস্তব মেমোরি)

আমরা আগেই বলেছিলাম, আপনার ৮ জিবির র‍্যামে আপনি ১২ জিবির অ্যাপ চালাতে পারেন। কিন্তু কীভাবে? 
এর উত্তর হলো **Virtual Memory**। 

OS আপনাকে এবং আপনার অ্যাপগুলোকে একটি বিভ্রম (Illusion) দেয় যে, আপনার পিসিতে বিশাল বড় মেমোরি আছে। 
**লজিক:**
- আপনি যখন ১২ জিবির অ্যাপ ওপেন করেন, OS পুরো ১২ জিবি র‍্যামে লোড করে না।
- আপনি অ্যাপের যে অংশটুকু বর্তমানে ব্যবহার করছেন (যেমন: গেমের শুধু লেভেল-১), OS শুধু ততটুকু অংশকেই (কয়েকটি Pages) RAM এ লোড করে।
- বাকি অংশটুকু সে হার্ডডিস্কের একটি বিশেষ জায়গায় লুকিয়ে রাখে (যাকে Windows এ 'Pagefile' এবং Linux এ 'Swap Space' বলে)। 

---

## 5. Page Fault & Swapping

**Page Fault:**
ধরা যাক, আপনি গেম খেলতে খেলতে লেভেল-২ তে চলে গেলেন। CPU তখন লেভেল-২ এর ডেটা (Page) RAM এর কাছে চাইবে। কিন্তু RAM এ তো লেভেল-২ নেই (কারণ তা হার্ডডিস্কে রাখা ছিল)! 
যখন CPU এমন কোনো Page চায় যা বর্তমানে RAM এ নেই, তখন তাকে **Page Fault** বলে।

**Swapping (বা Paging In/Out):**
Page Fault হলে OS দ্রুত হার্ডডিস্কের কাছে যায়। RAM যদি ফুল থাকে, তবে RAM থেকে অপ্রয়োজনীয় একটি Page কে হার্ডডিস্কে পাঠিয়ে দেয় (Swap Out) এবং লেভেল-২ এর Page টিকে হার্ডডিস্ক থেকে RAM এ নিয়ে আসে (Swap In)। 
এই পুরো প্রসেসটি এত দ্রুত ঘটে যে ইউজার টেরই পায় না যে তার RAM কম ছিল!

*(নোট: তবে আপনার পিসির RAM যদি খুব কম হয়, তখন OS কে বারবার Swap করতে হয়। হার্ডডিস্ক যেহেতু স্লো, তাই পিসি তখন হ্যাং বা ল্যাগ করা শুরু করে। একে 'Thrashing' বলে)।*
