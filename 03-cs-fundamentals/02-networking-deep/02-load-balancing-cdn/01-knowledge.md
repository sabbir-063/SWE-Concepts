# 02. Load Balancing & CDN (Knowledge & Theory)

## Learning Objectives
- Load Balancer কী এবং এর বিভিন্ন অ্যালগরিদম (Round Robin, Least Connections) সম্পর্কে ক্লিয়ার আইডিয়া পাওয়া।
- Layer 4 (L4) এবং Layer 7 (L7) Load Balancing এর মধ্যে পার্থক্য বোঝা।
- CDN (Content Delivery Network) কী এবং Edge Servers কীভাবে ওয়েবসাইটের স্পিড রকেটের মতো ফাস্ট করে তা বোঝা।
- ক্যাশিং (Caching) এর বেসিক কনসেপ্ট ক্লিয়ার করা।

---

## 1. What is a Load Balancer?

ধরা যাক, আপনার ওয়েবসাইটে আগে প্রতিদিন ১০০ জন ভিজিটর আসতো, যা একটি সার্ভার (Server 1) সহজেই হ্যান্ডেল করতে পারতো। 
এখন হঠাৎ করে আপনার ওয়েবসাইট ভাইরাল হয়ে গেলো এবং প্রতিদিন ১ লক্ষ মানুষ আসা শুরু করলো। আপনার ওই একটি সার্ভার এত প্রেসার নিতে না পেরে ক্র্যাশ করবে।

এর সমাধান হলো **Horizontal Scaling** (আরও সার্ভার যোগ করা)। আপনি আরও ৩টি সার্ভার কিনলেন (Server 2, 3, 4)। 
কিন্তু ইউজাররা যখন `yourwebsite.com` লিখে হিট করবে, তখন তারা কোন সার্ভারে যাবে? 

এখানেই আসে **Load Balancer**। এটি ট্রাফিকের (ইউজারদের) সামনে একজন ট্রাফিক পুলিশের মতো দাঁড়িয়ে থাকে। সব ইউজার প্রথমে Load Balancer এর কাছে রিকোয়েস্ট পাঠায়, আর Load Balancer সেই রিকোয়েস্টগুলোকে পেছনের ৪টি সার্ভারের মধ্যে সমানভাবে ভাগ করে দেয়। ফলে কোনো একটি সার্ভারের ওপর অতিরিক্ত প্রেসার পড়ে না।

## 2. Load Balancing Algorithms (কীভাবে ভাগ করে?)

Load Balancer কয়েকটি নিয়মে রিকোয়েস্ট ভাগ করে দেয়:

1. **Round Robin:** সিরিয়াল অনুযায়ী কাজ করে। প্রথম রিকোয়েস্ট সার্ভার-১ কে দেয়, দ্বিতীয়টা সার্ভার-২ কে, তৃতীয়টা সার্ভার-৩ কে... আবার শুরু থেকে। (সব সার্ভারের সাইজ সেম হলে এটি বেস্ট)।
2. **Least Connections:** যেই সার্ভারে বর্তমানে সবচেয়ে কম ইউজার কানেক্টেড আছে, নতুন রিকোয়েস্টটা সেই সার্ভারেই পাঠায়।
3. **IP Hash:** ইউজারের IP Address কে হ্যাশ (Hash) করে ঠিক করে সে কোন সার্ভারে যাবে। এর সুবিধা হলো, একজন ইউজার সবসময় একটি নির্দিষ্ট সার্ভারেই যায়। (সেশন/লগইন ধরে রাখার জন্য এটি খুব কাজের)।
4. **Weighted Round Robin:** আপনার যদি একটি সার্ভার খুব পাওয়ারফুল এবং অন্যটি একটু দুর্বল হয়, তবে আপনি পাওয়ারফুল সার্ভারটিকে বেশি ওয়েট (Weight) দিতে পারেন, যাতে সে বেশি রিকোয়েস্ট পায়।

## 3. Layer 4 vs Layer 7 Load Balancing

Load Balancing মূলত OSI মডেলের দুটি লেয়ারে কাজ করে:

### Layer 4 (Transport Layer - TCP/UDP)
- এটি শুধু ইউজারের IP Address এবং Port Number দেখে রিকোয়েস্ট ফরওয়ার্ড করে।
- প্যাকেটের ভেতরে কী ডেটা আছে (যেমন URL বা Cookies) তা সে দেখে না।
- **সুবিধা:** অনেক ফাস্ট এবং সিকিউর।
- **ব্যবহার:** ডাটাবেস বা গেম সার্ভারের লোড ব্যালান্স করতে।

### Layer 7 (Application Layer - HTTP/HTTPS)
- এটি প্যাকেটের ভেতরের আসল ডেটা (HTTP Headers, URL, Cookies) পড়তে পারে।
- এর মানে হলো, এটি অনেক স্মার্ট ডিসিশন নিতে পারে। যেমন: URL এর শেষে যদি `/images` থাকে, তবে সে রিকোয়েস্টটি শুধু ইমেজ সার্ভারে পাঠাবে। আর `/api` থাকলে API সার্ভারে পাঠাবে। 
- **সুবিধা:** স্মার্ট এবং ফ্লেক্সিবল।
- **ব্যবহার:** ওয়েব অ্যাপ্লিকেশনের (Microservices) জন্য এটি সবচেয়ে বেশি ব্যবহৃত হয়।

## 4. What is a CDN? (Content Delivery Network)

ধরা যাক, আপনার মেইন সার্ভার আমেরিকায় (USA) অবস্থিত। বাংলাদেশ থেকে একজন ইউজার যখন আপনার ওয়েবসাইটের একটি ছবি (Image) দেখতে চাইবে, তখন সেই ছবির ডেটা আমেরিকা থেকে বাংলাদেশে আসতে অনেক সময় লাগবে (High Latency)।

এই সমস্যার সমাধান হলো **CDN**। 
CDN হলো সারা পৃথিবীতে ছড়িয়ে থাকা অনেকগুলো সার্ভারের একটি নেটওয়ার্ক। এগুলোকে **Edge Servers** বলা হয়। 

**কীভাবে কাজ করে?**
- যখন বাংলাদেশের ইউজার প্রথমবার ছবিটি রিকোয়েস্ট করে, তখন Edge Server আমেরিকা থেকে ছবিটি এনে ইউজারকে দেয় এবং নিজের কাছে একটি কপি সেভ করে রাখে (Caching)।
- এরপর বাংলাদেশের অন্য কোনো ইউজার যদি ওই একই ছবি রিকোয়েস্ট করে, তবে Edge Server আর আমেরিকায় যাবে না। সে নিজের কাছে থাকা কপিটিই সাথে সাথে ইউজারকে দিয়ে দেবে।
- এর ফলে ওয়েবসাইটের স্পিড রকেটের মতো ফাস্ট হয়ে যায় এবং মেইন সার্ভারের ওপর থেকে বিশাল প্রেসার কমে যায়!

**পপুলার CDN প্রোভাইডার:** Cloudflare, AWS CloudFront, Akamai.

---

## 5. What does a CDN Cache?
CDN মূলত **Static Content** ক্যাশ (Cache) করে। Static Content হলো সেইসব ডেটা যা সহজে চেঞ্জ হয় না। যেমন:
- Images (JPG, PNG)
- CSS এবং JavaScript ফাইল
- Videos (MP4)
- Fonts

*(নোট: ডাইনামিক কন্টেন্ট, যেমন ইউজারের ব্যাংক ব্যালান্স বা শপিং কার্ট, সাধারণত CDN এ ক্যাশ করা হয় না। কারণ এগুলো ঘন ঘন চেঞ্জ হয় এবং প্রতি ইউজারের জন্য আলাদা হয়)।*
